## Полученный результат

Самостоятельный проект: **`D:\Code Projects\noiselab`**. Существующие пользовательские репозитории не изменялись. Выполнены браузерная версия и Windows unpacked-приложение Electron. ## Проведённые тесты

**`npm test`: 25/25 прошли.** WAV mono/stereo; 44.1/48 kHz; PCM16/24/32, Float32 и extensible PCM; Unicode; повреждённые/неподдерживаемые файлы; NaN/Infinity; RIFF odd padding; very short silence; явное clipping; точные границы resampling; подавление алиасинга; 20-минутное блочное чтение; отмена; transferable PCM accounting; запрет недоступной модели даже при wet=0.

**`npm run test:browser`: 19 групп проверок прошли.** Это настоящие исполнения RNNoise/WASM и GTCRN/WASM с встроенными модельными весами, без mock inference:

- Ненулевой конечный результат, отличие от зашумлённого входа, независимые stereo states.
- Одинаковая обработка при блоках 1 и 31 model frames на 44.1/48 kHz, без изменения длины и дрейфа.
- 1/17/489 samples тишины, завершающие фреймы, повторный reset, идемпотентный destroy и стабильная линейная WASM memory при 40 reset.
- Импульсы около model/block границ и в конце файла: сохранение временного положения в пределах ±5 отсчётов. Амплитуды изолированных импульсов могут быть очень малы: шумодав вправе подавлять такой неречевой сигнал. Этот тест проверяет timing, не сохранность речевого качества.
- Настоящие Worker previews; загрузка Unicode WAV через File input; A/B во время play; Pause/Play и Loop.
- Dry/Wet без нового inference. Экспорт PCM24 stereo декодирован обратно: длина совпала, ошибка относительно выбранной 37% смеси <`3e-7`.
- Сравнительный cold/repeat UI benchmark; реальная потоковая обработка и воспроизведение. В обычном коротком real-time тесте были **0 underruns**. Намеренная задержка подачи настоящих GTCRN-блоков была обнаружена как underrun, готовый вариант не подставлялся.
- Перемотка/выделение мышью; Drag & Drop; повторная загрузка; отмена и восстановление Worker; масштабы 100/125/150% без горизонтального переполнения; RU/EN; отсутствие внешних запросов и uncaught UI errors.

Машинные свидетельства: `test-output/model-tests.json`, `browser-tests.json`, `noiselab.png`.

**`npm run test:electron` и прямой запуск `NoiseLab.exe` с тестовым режимом прошли.** Проверены настоящий Windows-процесс, обе WASM-модели, running Web Audio, contextIsolation/nodeIntegration, реальный File API с Unicode WAV, запись WAV через ограниченный IPC, точная длина RIFF, удаление temp при отмене и защита исходного WAV от перезаписи. Дополнительно проверено закрытие окна во время Worker job с уже поступающими обработанными блоками и незавершённым экспортом: временный файл удалился; повторный запуск проверен отдельным процессом. Логи: `test-output/electron-smoke.log`, `electron-close.log`.

В тестовом режиме путь Save As подставлялся только для собственного временного тестового файла. Ручное взаимодействие с системным Save As, слушательская проверка реального аудиовыхода и оценка естественности голосов не проводились. ## Сравнительная производительность

Фактически измерено на **AMD Ryzen 7 5700X, 16 logical cores, 31.9 GiB RAM, Windows 10 x64**, на CPU. GPU не использовался.

Вход — 48 kHz mono PCM16, 10.596 s шумной речи из официального `DeepFilterNet/assets/noisy_snr0.wav`, повторённый до ровно 1/5/20 минут. Источник закреплён commit `d375b2d8309e0935d165700c91da9de862a99c31`. Это реальные вычисления на WAV с речью, **не уникальные пользовательские 1/5/20-минутные записи**. Повтор эталона может влиять на модельное состояние; значения не гарантируют скорость для любого материала.

| Модель | Длительность WAV | Inference | Полный пайплайн | RTF inference | WASM memory |
|---|---:|---:|---:|---:|---:|
| RNNoise | 1 min | 5.47 s | 6.06 s | 0.0911 | 19.6 MiB |
| GTCRN | 1 min | 1.94 s | 3.41 s | 0.0323 | 16.7 MiB |
| RNNoise | 5 min | 27.53 s | 30.17 s | 0.0918 | 19.6 MiB |
| GTCRN | 5 min | 8.86 s | 15.51 s | 0.0295 | 16.7 MiB |
| RNNoise | 20 min | 109.30 s | 120.07 s | 0.0911 | 19.6 MiB |
| GTCRN | 20 min | 35.80 s | 60.21 s | 0.0298 | 16.7 MiB |

Полный пайплайн включает чтение, передискретизацию, RMS/Peak и PCM24-кодирование каждого выходного блока. Запись на диск и fsync большого файла в этом бенчмарке **не включены**. Поэтому результат укладывается в ориентир 5 минут для измеренных вычислений, но полный экспорт 20-минутного проекта с прочими операциями не обещается и отдельно не измерен.

Первая загрузка в benchmark: RNNoise 53.4 ms, GTCRN 8.3 ms; следующие прогоны использовали кеш WASM и новые model states. Максимальная наблюдаемая оценка рабочих PCM-блоков — 46,146 samples RNNoise и 24,642 GTCRN для mono; она одинакова для 1/5/20 min. Доступная JS heap на окончаниях прогонов была около 22–44 MiB с колебаниями GC. WASM memory постоянна. Это не общий RSS Electron и не доказательство отсутствия всех возможных утечек.

**Оценка**, не отдельный замер: 100 независимых реплик по 5 s потребуют примерно 45.5 s чистого inference RNNoise или 14.9 s GTCRN по пропорции из длинного тёплого прогона. Сбросы, запуск состояний, граничные фреймы, ресэмплинг и запись увеличат полное время. Данные: `test-output/benchmark.json`.

## Высокочастотные детали

Отдельный прогон настоящих весов на 10.596 s шумного эталона измерил FFT-полосу ≥8 kHz: RNNoise около **-1.5 dB**, GTCRN около **-61.7 dB** относительно входа. Доля этой полосы у входа 4.79%, у RNNoise 4.36%, у GTCRN практически нулевая. Метод: 1024-point Hann FFT, шаг 4096 samples (`tools/quality-probe.mjs`, `test-output/high-frequency.json`).

Это показывает ожидаемое ограничение GTCRN 16 kHz: модель не сохраняет верхнюю полосу Wet. Энергия шумной записи включает и шум, поэтому эти значения **не доказывают** качество шипящих, сохранение тембра или превосходство RNNoise. Для этого нужен A/B на собственной записи, без скрытой громкостной компенсации.

## Лицензии

RNNoise wrapper — Apache-2.0; официальный RNNoise runtime source — BSD-3-Clause. GTCRN wrapper и встроенные веса `gtcrn_simple` — MIT, с явным model notice в опубликованной сборке; pffft — UCAR/FFTPACK terms. Эти лицензии кода и явная MIT-лицензия GTCRN-модели допускают распространение и коммерческое использование при соблюдении условий и сохранении notice texts. Тексты и происхождение разнесены в `THIRD_PARTY_NOTICES` и `licenses/`; хеши относятся к выбранным опубликованным WASM-артефактам, без утверждения независимой побайтовой пересборки.

**Отдельно проверены именно веса RNNoise:** официальный model archive скачан с Xiph, его SHA256 совпал с закреплённым `model_version`. В нём есть `src/rnnoise_data.c/h`, little-вариант и `rnnoise10Ga_12.pth`/`rnnoise10Gb_15.pth`, но нет отдельного LICENSE, а generated C/H не содержат лицензионных заголовков. Официальный BSD-проект распространяет этот default model как штатный вход своей сборки; применение BSD к конкретным весам — обоснованное предположение, а не отдельно подтверждённое разрешение. **Безусловное коммерческое распространение этих весов не объявляется подтверждённым.** Для устранения неопределённости нужно получить подтверждение Xiph/Jean-Marc Valin о покрытии именно архива этим разрешением, сохранив hash и ответ. Локальные тесты и предоставленная локальная сборка используют настоящий опубликованный WASM. Свидетельства: `research/rnnoise-model-audit.json` и `rnnoise-model-headers.txt`. Проект не публиковался.

DeepFilterNet3 C-порт не имеет явной лицензии на собственный код в проверенной revision. Официальный Rust backend имеет WASM feature и CI build; поэтому он не объявлен технически невозможным. Однако выбранный официальный WASM не собран/подключён, lifecycle raw-pointer API требует доработки, а права именно на модельный artifact отдельно не установлены. Код и веса C-порта не включены. [Подробности и путь завершения](deepfilternet3.md).

`npm audit` на дату проверки: 8 moderate issues в цепочке **build-time electron-builder → global-agent/roarr/sprintf-js**, high/critical = 0. Это не npm runtime dependencies моделей. Отчёт сохранён в `test-output/npm-audit.json`. Не выполнен предложенный npm принудительный downgrade сборщика до 26.5.0; он изменил бы уже проверенную сборочную среду. Runtime аудио не форматируется этой библиотекой.

## Что не завершено и ограничения

- **DeepFilterNet3** не интегрирован: подтверждённый лицензионный блокер готового C-порта и незавершённый официальный путь. Подготовленный адаптер явно недоступен.
- Классический Wiener/STFT не добавлен; он был опционален.
- Не проведена субъективная оценка голосов, шёпота, шипящих и эмоциональных реплик пользователя. Победитель по естественности не назначается.
- Не проверен полный большой экспорт с дисковым fsync на уникальной пользовательской 20-минутной записи; бенчмарк использовал повтор речи и PCM-кодирование без сохранения большого выхода.
- Real-time поддерживает A/B Original/текущая модель; seek, Loop, LUFS и переход на другую модель требуют остановки. Все эти функции доступны в обычном preview.
- Предел preview — 60 s и 12 MiB PCM на вариант; обычный браузерный Blob download — 128 MiB. В Electron/FSA экспорт потоковый. RIFF ограничен 4 GiB, RF64 не реализован.
- Поддержаны 1–2 канала, PCM16/24/32 и Float32, 8–192 kHz. Другие WAV-кодеки и multichannel явно отклоняются.
- LUT sinc и нейросетевой DSP могут менять фазу по частотам; общая задержка компенсирована, полная фазовая идентичность Dry/Wet не обещается.
- Осциллограмма использует прореженные отсчёты длинных записей и может не показать одиночные узкие пики.
- LUFS-измеритель не сертифицирован; sound quality нельзя выводить только из RMS, FFT или RTF.

Приложение представляет работающее состояние с двумя настоящими нейросетевыми алгоритмами и честно недоступным третьим. Полное выполнение всех пунктов ТЗ без перечисленных ограничений не заявляется.
