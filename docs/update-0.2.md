# NoiseLab 0.2 — OGG и устойчивость окна

14 октября 2026 года.

## Входные форматы

Добавлены OGG Vorbis и OGG Opus, mono/stereo. В меню выбора файла доступны `.ogg` и `.opus`, также работает Drag & Drop. Первые байты проверяются до изменения текущей записи: неподдерживаемый WebM показывает ошибку и сохраняет прежний WAV/OGG и его результаты.

OGG сначала читается постранично в отдельном Worker. Проверяются границы страниц, stream serial, порядок и CRC; поддержан один полный логический аудиопоток. Vorbis декодируется на родной частоте, Opus — на 48 kHz. Сэмплы с учётом codec pre-skip/end granule записываются как Float32 WAV в локальный OPFS, без накопления полного PCM в JS-памяти. Затем используются тот же WAV loader, neural pipeline и A/B-плеер. На диске требуется место под полный decoded PCM.

Обработанные результаты и декодированный Original сохраняются в WAV. «Копия оригинала» для OGG сохраняет побайтную копию OGG, без повторного lossy encoding. Кодирование обработанного результата в OGG не добавлено.

Временный файл удаляется при следующей загрузке; после аварийного завершения Electron очищает своё браузерное файловое хранилище на следующем старте. Обычная браузерная версия может оставить temp в storage после аварии. Тесты проверяют сохранение числа сэмплов и работу в локальном хранилище; крайние сценарии disk full/OS kill отдельно не воспроизводились.

## Устойчивость

Пользователь сообщил, что окно исчезло, будучи свёрнутым, ещё до выбора WAV. В прошлой версии отсутствовали журнал событий и локальные native crash dumps; Windows не предоставил пригодных записей для установления причины. **Точная причина прежнего вылета не доказана.**

В версии 0.2:

- Отрисовка UI выполняется без аппаратного ускорения; WASM-модели по-прежнему работают на CPU. Это устраняет GPU-зависимость интерфейса, но не является доказательством, что прежний вылет был связан с GPU.
- Один пользовательский экземпляр приложения; повторный запуск показывает существующее окно. Все тесты используют отдельные профили, не затрагивая пользовательский cache/OPFS, и скрыты из панели задач.
- Локальные startup/minimize/restore/close/quit и crash-события сохраняются в `%APPDATA%\noiselab\logs\noiselab.log`, с ограничением размера журнала.
- Native dumps находятся рядом в `crashes/`. `uploadToServer` явно false, submit URL отсутствует. Журнал не содержит PCM. Дамп памяти может содержать фрагменты процесса и хранится локально.
- После падения renderer выполняется ограниченное восстановление: незавершённый экспорт удаляется, интерфейс перезагружается и сообщает, что нужно открыть аудиофайл повторно. Падение всего main process не объявляется автоматически восстановленным.

## Фактические проверки

- `npm test`: **29/29** прошли, включая настоящие Vorbis/Opus, mono/stereo, 44.1/48 kHz. Длина соответствует FFmpeg reference decode; RMS расхождения PCM <`2e-5`. Проверены CRC, повреждённые/обрезанные OGG и ограничения размера page reads. FFmpeg используется только для создания и независимой проверки тестовых файлов.
- `npm run test:ogg:browser`: четыре сочетания codec/channel прошли локальное декодирование в OPFS, RNNoise, GTCRN, play, WAV export и отказ WebM с сохранением текущей записи. Внешние запросы и uncaught errors отсутствовали.
- `npm run test:ogg:electron`: те же четыре сочетания прошли настоящий File input, OPFS decode, RNNoise/WASM, native WAV save и побайтное копирование оригинального OGG через системный IPC.
- `npm run test:browser`: 19 групп регрессионных проверок WAV, A/B, Loop, strength, real-time, export, cancel/reload и масштабов интерфейса.
- `npm run test:electron`: настоящий WAV/WASM/Web Audio, IPC export, защита исходника и закрытие во время обработки сохранили рабочее состояние.
- `npm run test:stability`: окно оставалось свёрнутым **120 секунд**, процесс и интерфейс работали; WebM был отклонён без завершения приложения.
- `npm run test:recovery`: управляемый сбой renderer восстановлен, `uploadToServer=false` проверен.

Эти проверки подтверждают конкретные сценарии и не гарантируют отсутствие всех возможных длительных вылетов. Долгие пользовательские OGG на 20–30 минут пока не служили эталоном данной регрессии; архитектура не хранит их decoded PCM целиком в памяти.

## Новые компоненты

`@wasm-audio-decoders/ogg-vorbis@0.1.20`, `ogg-opus-decoder@1.7.5`, common 9.0.7, opus-decoder 0.7.12, codec-parser 2.5.0 и simple-yenc 1.0.4. Бандлы собираются из опубликованных npm-исходников через esbuild 0.28.2; codec bytes не заменяются собственной реализацией. Опциональные ML-улучшения Opus отключены и не участвуют в обработке.

Wrappers/common — MIT, libvorbis/libogg/libopus — Xiph BSD terms, codec-parser — **LGPL-3.0-or-later**. Предоставлены тексты LGPL и включённого GPL, parser/decoder JS sources и команда `npm run vendor` для замены и пересборки LGPL-библиотеки. Подробности: `THIRD_PARTY_NOTICES`, `licenses/`, `licenses/dependencies.json`. Наличие MIT у обёртки не меняет условий parser.

Исходные измерения RNNoise/GTCRN из `docs/report.md` относятся к предыдущему бенчмарку WAV и не выдаются за заново измеренную скорость OGG-декодирования.
