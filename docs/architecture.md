# Архитектура NoiseLab

В 0.3 DFN3 использует официальный Rust/Tract WASM в общем Worker. Внешний ModelFile проверяется по SHA256, каждый канал имеет своё состояние с парным df_free. Delay 1440, у native 0 dB bypass — 0. ABPlayer последовательно меняет контексты и игнорирует старый revision; Jobs привязывает ACK/ошибки к конкретной задаче. Запомненная модель читается через ограниченный IPC без renderer-команд. Подробнее: `docs/deepfilternet3.md`.

Версия 0.2 также принимает OGG: `audio/ogg.js` проверяет последовательность и CRC страниц, затем декодирует через local libvorbis/libopus WASM в Worker и пишет Float32 WAV в OPFS. Пайплайн ниже получает этот File и сохраняет прежний контракт чтения блоками. Исходный OGG хранится отдельно для неизменённой копии; временный PCM не заменяет пользовательский файл. Подробнее: `docs/update-0.2.md`.

## Слои

`public/js/algorithms/index.js` содержит registry и общий `createDenoiser({algorithm, channels})`. Адаптер знает только PCM, WASM и модель: `metadata`, `process`, `flush`, `reset`, `destroy`, `memoryBytes`. UI, DOM, Worker-сообщения и Electron IPC в нём отсутствуют. `process` принимает строго один native frame на канал; произвольные входные блоки и sample rate обслуживает внешний пайплайн. `flush` подаёт один нулевой фрейм; пайплайн подаёт столько завершения, сколько требуется конкретной задержке.

RNNoise: Float32 [-1,1] умножается на 32768 перед native вызовом и делится обратно. `DenoiseState.processFrame` меняет входной буфер на выход и отдельно возвращает VAD. По одному DenoiseState на канал. GTCRN: один GtcrnProcessor на канал при native 16000 Hz. Готовый native 48 kHz resampler обёртки не используется: единый sinc-пайплайн контролирует обе частоты и временные координаты. Весовая модель остаётся настоящей скомпилированной сетью из пакета.

Модули загружаются один раз в пределах Worker. Каждый независимый прогон создаёт свежие состояния; `reset` уничтожает и воссоздаёт их. `destroy` идемпотентен и вызывается в finally. Кеш сохраняет WASM module/weights, не состояние речи и не аудиозаписи. Отмена принудительно завершает Worker и освобождает его целиком; следующий прогон создаёт новый.

## WAV и ограничение памяти

`audio/wav.js` читает RIFF-заголовки и fmt/data chunk через `file.slice().arrayBuffer()`, проверяет границы, alignment, GUID и формат. Чтение audio и Unicode-пути выполняет браузерный File API, без передачи произвольного пути в Node.js. PCM декодируется блоками из interleaved в planar Float32. Stereo сохраняется. Не используется `decodeAudioData` всего файла.

Осциллограмма удерживает 1600 min/max пар и максимум 4 секунды decoded PCM. Она прореживает просмотр длинных записей до примерно 256 отсчётов на bin. Это обзор, не точный sample editor.

Предпрослушивание допускает максимум 60 s и 12 MiB на один PCM-вариант. Web Audio делает собственные копии ограниченных AudioBuffer. UI удерживает Original и до трёх Wet для одного участка — максимум 48 MiB исходных PCM-массивов плюс копии Web Audio. Число вариантов не растёт с длиной файла. Новый участок удаляет предыдущие варианты.

Экспорт и real-time читают фиксированное количество model frames за раз (32 для экспорта, 4 для потока). OutputResampler удерживает только текущий блок и sinc history. Backpressure для записи и потока осуществляется ACK на каждый блок. Обычное браузерное Blob-скачивание — явно документированное исключение с лимитом 128 MiB.

## Координаты и передискретизация

1. Выделение представлено точными целыми source sample indices `[start,end)`.
2. Добавляется до 250 ms контекста до start, чтобы модель услышала ближайшее прошлое; состояние не переносится с другого независимого опыта.
3. Вход переводится в native rate симметричной 64-tap Blackman sinc, 1024 fractional phases. Координаты вычисляются от абсолютного индекса, а не округляются заново на каждой границе блока. Halo отсчёты читаются вокруг блока, но ограничены выбранным концом и началом контекста.
4. PCM передаётся целыми фреймами без разрыва состояния. Последний неполный фрейм дополняется нулями; затем подаются нулевые фреймы, покрывающие delay и resampler halo.
5. У RNNoise этой версии задержка **960 samples**, а не 480: overlap STFT плюс delayed spectrum. У GTCRN native 16 kHz задержка **256 samples**. Эти отсчёты удаляются из выхода.
6. OutputResampler начинает выборку ровно с рациональной native координаты выбранного source start. Выход имеет **точно end-start source samples**, включая первое и последнее слово. Дополнение используется для flush, а не добавляется в WAV.
7. Dry повторно читается из того же участка исходного файла. Dry/Wet `(1-wet)*Dry + wet*Wet`, причём при wet=0 возвращаются исходные decoded отсчёты без ресэмплинга и без модели.

Симметричный sinc не добавляет причинного группового сдвига в офлайн-сравнение. В live-WAV обработке необходимый будущий halo считывается из уже существующего файла. Фазовые изменения самой сети/её DSP остаются частью слышимого результата. Компенсация общей задержки не отменяет их.

## Воспроизведение

ABPlayer хранит cursor в координатах исходного WAV. Одновременно проигрываются Dry и выбранный Wet с одинаковыми sample rate, offset и clock. Коэффициенты ramp 20 ms. При смене Wet-модели старый GainNode затухает, а новый запускается с текущим source offset. Оригинал всегда отдельный PCM исходника; никакого dry reconstruction из шумоподавленного звука нет.

Pause сохраняет позицию; Loop использует одинаковые границы буферов. LUFS-поправка — отдельный gain для audition после линейной смеси. На сохранённый PCM она не влияет. Алгоритм K weighting адаптирует коэффициенты к sample rate и применяет 400 ms окна с абсолютным -70 LUFS и относительным -10 LU gating. Точность не сертифицирована.

Real-time использует тот же processWav с меньшими блоками, не готовые preview buffers. Worker выдаёт Dry/Wet блок, плеер планирует пару источников с общим временем. ACK ограничивает горизонт очереди приблизительно prebuffer+0.2 s. Если дедлайн пропущен, счётчик увеличивается и возникает слышимый разрыв. Последовательность модели не сбрасывается. Перемотка/Loop в этом режиме требуют нового прогона; обычный A/B-preview поддерживает их полностью.

## Измерения

initMs — загрузка и создание состояния; cached сообщает reuse модуля. computeMs — только синхронные вызовы моделей; totalMs — весь пайплайн, включая ожидание onChunk. RTF = computeMs/(duration*1000). Для решения об экспорте оценивать также totalMs; в real-time он содержит backpressure ожидание аудиочасов. memoryBytes — текущая линейная WASM memory; maxBufferedSamples — верхняя наблюдаемая оценка PCM-блоков пайплайна, не полный RSS. RMS/Peak измеряются до/после; это диагностические величины, а не оценка естественности голоса.

## Electron и безопасность

Локальный Node HTTP-сервер отдаёт только `public/`, GET/HEAD, проверяет Host и path containment. CSP допускает только собственные скрипты, Worker и WASM, запрещает внешние подключения, объекты и frames. На сеть renderer накладывается дополнительно Electron request filter. Права camera/microphone запрещены.

Окно: contextIsolation=true, nodeIntegration=false, sandbox=true. Preload ограничен save begin/write/finish/abort, версиями и измерением памяти main process. IPC проверяет sender, main-frame URL, имя WAV, размер, token, byte type и границы chunk. Путь назначения выбирает исключительно main process через Save As, не renderer. Открытие внешних окон и навигация запрещены.

Экспорт: exclusive temp file в каталоге назначения, последовательная запись, проверка total bytes, fsync, проверка изменения назначения после диалога, rename. Отмена/закрытие удаляет temp. При аварийном убийстве ОС может остаться файл `.noiselab-<UUID>.tmp`; автоматическое удаление произвольных чужих файлов не производится.

## Извлечение модулей

Для другого браузерного/Electron приложения достаточно перенести `audio/`, `algorithms/` и соответствующие `vendor/` с license notices. `processWav` использует File-like `size/slice/arrayBuffer`, callbacks onChunk/onProgress/cancelled. Системная запись, кнопки и IPC не требуются. RNNoise npm-сборка ориентирована на browser/Worker и напрямую в Node без браузера не запускается; реальные интеграционные проверки выполняются Puppeteer/Electron.
